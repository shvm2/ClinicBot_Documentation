01 / Overview

Not just a chatbot.

ClinicBot was built as a reusable automation backend: conversation state, API integration, persistence and business configuration are separated instead of being tied together in one-off message handlers.

02 / Architecture

Designed around separation of concerns.

The state machine stays independent of the database and WhatsApp API. Side effects are orchestrated by services; storage is isolated behind repositories.

05 / Why I built it

I wanted to build the automation engine, not just a scripted bot.

I built ClinicBot to explore what it takes to turn a WhatsApp workflow into a reusable backend system. The goal was to keep conversational logic, persistence and platform integration separate so the same underlying engine could be adapted to different appointment-based businesses through configuration.
